## Problem and approach

Customer delivery requests can overlap and create peaks in simultaneous truck requirements even when total daily demand is manageable. The model shifts complete customer demand profiles within feasible time windows to minimize the daily peak. A movement budget limits how many customers may be rescheduled; lexicographic objectives then minimize the number and magnitude of changes. The recovery extension reoptimizes a limited set of requests after some proposed first-stage changes cannot be implemented.

This is a temporal capacity-smoothing model. It does not construct routes or assign individual vehicles. Customer acceptance in the extension is simulated rather than estimated from observed behavior. Recovery changes are assumed to be implementable, a limitation discussed in the thesis.

## Selected numerical findings

The study uses 30 days of **generated, empirically motivated demand data**, 15-minute intervals and up to ±60 minutes of scheduling flexibility. The findings describe this experimental dataset, not realized savings at a company.

| Experiment | Mean daily peak reduction | Mean customers moved |
| --- | ---: | ---: |
| Unrestricted, ±60 minutes | 36.07% | 74.27% |
| 20% requested movement budget, ±60 minutes | 17.96% | 17.49% |
| 50% requested movement budget, ±60 minutes | 29.87% | 44.14% |

The final recovery study uses 100 scenarios per day and implementation probability, with random seed 20260503. Its three probabilities and three recovery budgets produce 27,000 scenario-result rows. The final summary tables and day-clustered confidence bands are retained under `results/`.

## Files

- `code/minimax_rescheduling_budget_implementation.py`: deterministic MILP, flexibility and disruption-budget experiments.
- `code/minimax_recoverable_rescheduling_implementation.py`: partial implementation and second-stage recovery experiments.
- `code/generate_recovery_ci.py`: validation of scenario results, Table 15 and 95% confidence-band calculations.
- `data/customer_requests.csv`: generated input data used in the submitted thesis.
- `results/`: final aggregated deterministic results, Table 15 and recovery confidence bands.
- `requirements.txt`: original dependency list supplied with the thesis supplement.

These core implementation files, data and summary tables come from the supplement sent with the submitted thesis on 15 August 2026. Earlier exploratory extensions and preliminary 10-scenario outputs are omitted from this public project folder to keep the final model clear. The thesis PDF is the submitted version, unchanged.

## Run the experiments

From this `master-thesis` directory, using a Python environment with `scipy.optimize.milp` available:

```bash
python -m pip install -r requirements.txt
python code/minimax_rescheduling_budget_implementation.py \
  --input data/customer_requests.csv --out outputs_budget
MPLBACKEND=Agg python code/minimax_recoverable_rescheduling_implementation.py \
  --input data/customer_requests.csv --budget-out outputs_budget \
  --out outputs_recoverable --scenarios 100
```

The solver is **SciPy MILP with the HiGHS backend**. Gurobi was used in other portfolio projects, not in these final thesis scripts. The original scripts are preserved; the supplement did not pin package versions, so exact reruns may vary with the environment and solver time limits.

The confidence-band script accepts `--help` for the scenario CSV and output-directory arguments. It can be run on the newly generated recovery outputs. This repository includes the original final summary tables; the full Monte Carlo output is generated by the scripts above.
